# Testing code changes

The purpose of these scripts is to simply checking if recent code changes have made unwanted changes to the output files generated by the GitHub workflow that creates the example outputs.

Example outputs inside `tests/data/example_output` from the main branch are considered the "ground truth", and are what we are comparing to.

Uses a pixi environment (which has been defined in `pyproject.toml`, pixi environment can be created by running `pixi install` inside the root directory for the repo). This pixi environment has a couple of extra dependencies that are needed by the scripts that check the output. These dependencies are not needed by `amrrules` itself.

## Quickstart workflow

```bash
# on main branch - ensure latest example_outputs are pulled
git fetch origin && git checkout origin/main -- tests/data/example_output
# make code changes, test etc on a new branch
# now run all test data and compare back to example_outputs
pixi run check-regressions
```

New output files are written to `tests/data/local_output` and `tests/data/regression_diffs` contains a summary of differences between files. If a diff file is empty, this indicates that no changes have occurred.

## Updating test commands

All test commands are defined in `tests/scripts/example_commands.yaml`. This is the master list of commands that should be changed when new example data is being added. Also contains a section at the bottom of debug specific cases (for local debugging, not meant to be propogated into the main repo) - only relevant if generating the `launch.json` file for VSCode for this repo.

## Options

`pixi run check-regressions` points to `tests/scripts/check_regressions.py`, full options are:

```bash
  --only ONLY           Comma-separated case names to check (default: all)
  --include-debug-cases
  --skip-generate       Don't regenerate; just diff tests/data/local_output as it currently stands
  --ignore-cols IGNORE_COLS
                        Comma-separated columns to exclude from comparison (default: version)
```

Note that this script ignores the `version` column from the interpreted output, as this would change as the code updates and is not relevant to compare to.

`pixi run run-examples` will just run the examples, and not do the comparisons. Points to `tests/scripts/run_examples.py`. This script is also used in the `generate-example-outputs.yml` file which lieves in `.github/workflows`, and generates all the examples outputs when code is changed on the main branch. Full options are:

```bash
  --output-dir OUTPUT_DIR
                        Directory to write amrrules output to
  --only ONLY           Comma-separated case names to run (default: all)
  --include-debug-cases
                        Also run cases listed under debug_cases i
```

`pixi run generate-launch-json` creates a `launch.json` file that can be used inside VSCode for debugging purposes. Ensures that I'm using an identical set of commands as the GitHub workflow when debugging changes.

```bash
  --include-debug-cases
                        Also generate configs for cases under debug_cases in the manifest
```
